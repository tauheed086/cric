Act as a world-class senior product designer and sports tournament platform architect.

Design a complete **Desktop + Mobile UI/UX** for a **local cricket tournament scoring and management application** where **admins manually update match scores**, and those updates are instantly reflected in the public-facing app like a live score experience.

This is **NOT** an API-based live cricket app.
This is **NOT** for international live feeds.
This is a **custom local cricket tournament platform** for organizers, scorers, teams, and viewers.

The system should include two major sides:

1. **Admin / Scorer Panel**
2. **Public User App (Desktop + Mobile)**

The product should feel like a professional cricket scoring platform built specifically for local tournaments, academies, corporate leagues, societies, district events, and community cricket competitions.

-----------------------------------
1. PRODUCT GOAL
-----------------------------------
Create a full-featured cricket tournament application where tournament organizers can:

- Create and manage tournaments
- Add teams, players, venues, and officials
- Create fixtures and match schedules
- Update toss, playing XI, innings, scores, wickets, overs, extras, fall of wickets, partnerships, and results manually
- Assign man of the match
- Automatically calculate points table
- Automatically calculate top run scorers, top wicket takers, strike rate leaders, economy leaders
- Automatically calculate player rankings
- Automatically determine Player of the Series based on tournament performance rules
- Publish match updates that reflect instantly in the public app

And where public users can:
- View fixtures
- View match scores updated by admin in near-real-time
- Follow tournament progress
- View points table
- View player stats
- View team stats
- View scorecards
- View commentary or scoring updates if admin enters them
- See awards like Man of the Match and Player of the Tournament / Series

-----------------------------------
2. IMPORTANT CONSTRAINT
-----------------------------------
Do NOT design this as an external live API sports app.

Instead:
- Design it as an **admin-controlled scoring platform**
- The “live” experience comes from **manual admin/scorer updates**
- Public users should still feel like scores are updating live
- The UI must support local tournament workflows and operations
